# 辅导猫晚查寝

基于 [LYCaikano/fudaomao-auto-check-in](https://github.com/LYCaikano/fudaomao-auto-check-in) 的个人改版，提供 Windows 配置界面与 Linux/T6 定时签到、学校结果回查、QQ 通知和短信验证码填写通道。

## Home Assistant 多账号管理

安装 [HA 集成与 T6 管理服务](t6/README.md#home-assistant-多账号管理) 后，管理员可以从 HA 侧栏的“签到”管理多个用户，每个用户可添加多个任务。学校任务的名称及开始、结束时间从签到链接自动读取，首次尝试基准为任务开始五分钟后，结束时停止；星期、开始日期和实际签到位置分别配置。

新增流程：新建用户 → 填写别名、账号名称和密码 → 请求并填写学校短信验证码 → 粘贴近期辅导猫签到链接 → 读取任务名称与起止时间 → 确认时间并填写位置 → 尝试签到并保存。学校直接允许登录时会进入任务配置。短信验证十分钟有效，等待短信期间可以关闭页面，重新打开后从用户的“查看进度”继续。

例如学校任务21:00开始、23:50结束，首次尝试每天在21:05:00至21:07:00之间随机安排，23:50停止。每项任务每天独立保存时间和位置偏移，同一天重试与服务重启沿用；自动签到的位置在保存坐标50米内随机变化，并根据学校范围边界缩小偏移。保存坐标和手动操作保持原值。“读取任务信息”可重新获取已保存任务的学校时间；粘贴同一任务的近期链接会更新该任务的信息。

在手机通过 HTTPS 打开 HA，进入任务设置并点击“获取当前位置”，允许定位后自动填写 GCJ-02 经纬度和定位坐标描述，同时显示定位精度。可以继续填写楼栋门牌，点击保存后更新任务。定位使用本次设备采集结果，浏览器提供的 WGS-84 坐标由服务端通过现有 `eviltransform` 转换；应用不会请求外部地址解析服务。定位失败时显示原因，原有输入保留。

任务识别同时保存长期任务编号和名称，运行时查询北京时间当天的实例。试签前核实学校要求的签到方式及位置范围；有效配置保存后自动启用调度。试签发生在时间窗口外或学校尚未返回当天任务时，页面显示原因，后续按保存的时间执行。学校没有确认签到时，页面不会显示签到成功。拍照、扫码、NFC 等任务需要使用学校客户端。

每个用户的密码加密保存，学校会话单独存放；每项任务拥有独立配置、提交记录和每日重试计数。失败结束后等待五分钟，每项任务每天最多尝试二十次。页面提供修改别名、重新验证登录、添加任务、任务设置、暂停自动签到、检查状态和立即签到。

新增其他用户时可勾选“绑定Robin提醒”，获取十分钟有效的一次性绑定码。对方添加Robin QQ机器人后，在私聊发送 `/bind 绑定码`。绑定完成后，该账号的签到成功、失败节点和验证码链接仅发送到对应QQ；未绑定时不向本人转发。原有本人账号沿用既有提醒。其他QQ的普通消息、附件和控制指令不会进入本人的NanoMuse、拾笺或agents通道。

学校要求短信时，每次登录生成独立的公开HTTPS临时链接，无需登录HA。页面提交后显示正在核实，学校登录验证完成后链接立即失效；失败、取消和十分钟超时同样失效。每个链接仅接受首次提交，不公开返回验证码，程序中断后会撤销对应入口。

## 使用方式

Windows 使用 Python 3.12（64 位），依次运行 `01_安装环境.cmd`、`02_填写配置.cmd`。安装入口联网安装 `requirements.lock.txt` 中的依赖。填写校园卡号、密码、实际住宿地址以及高德或腾讯地图的 GCJ-02 坐标，完成登录初始化后再运行 `03_启用每日签到.cmd`。

`04_只读检查.cmd` 查询学校状态，`05_查看状态.cmd` 显示本机结果，`06_停用每日签到.cmd` 停用 Windows 任务。Windows 默认北京时间20:31开始、22:30截止；Linux/T6 的21:05重试规则见 [T6部署说明](t6/README.md)。

学校登录接口使用校园卡号。密码在 Windows 使用 DPAPI 加密，在 Linux 使用本机 Fernet 密钥加密；迁移时需要重新加密。首次配置与登录不会提交签到。

更换账号或重新填写密码后会清理旧学校会话，初始化将使用当前凭据重新登录。

## 签到规则

- 精确匹配“物理学院2026级本科生晚查寝”，每次从学校查询北京时间当天的实例。
- 将实际住宿位置由 GCJ-02 转换为 BD-09，范围校验和提交使用相同坐标。
- 提交前保存实例标记，提交后查询学校。只有学校确认已签到才记录成功；结果未知时保留标记，停止重复提交。
- 学校要求拍照、扫码、NFC 或其他方式时，在学校客户端处理。短信登录验证码可在 Windows 本机输入，或使用 T6 的 HTTPS 填写通道。

## 目录

| 位置 | 用途 |
| --- | --- |
| `attendance.py` | 改版签到入口、任务过滤、范围与时间检查、结果回查 |
| `lzu_api.py` | 学校登录和查寝接口 |
| `configure.py`、`secure_store.py` | 本机配置界面及凭据加密 |
| `install_task.py`、`scheduled.pyw` | Windows 计划任务 |
| `t6/` | Linux 调度、QQ 通知、短信验证码服务及部署模板 |
| `config.example.json` | 不包含凭据的配置模板 |
| `run.py` | 上游程序 |
| `docs/upstream-readme.md` | 上游原始说明 |

私人配置、密码文件、令牌、学校会话、签到记录、照片与本地执行计划均被 Git 忽略。使用后的运行目录不能直接作为源码提交。

## 验证

Windows 环境安装后运行：

```powershell
.venv/Scripts/python.exe verify_environment.py
.venv/Scripts/python.exe attendance.py --check
```

第一条只检查运行组件；第二条需要本人完成学校登录配置，只查询状态，不提交签到。T6 的 `verify_rules.py` 使用独立 SQLite 验证重试、通知节点和时间表达式，不发送通知、不提交学校任务。
